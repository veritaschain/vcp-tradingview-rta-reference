# VCP TradingView RTA PoC Verification Guide

The bundled pack is **NON-CERTIFIED** and does **not establish VCP v1.1 Silver conformance**. Its anchor is a local record. No real external timestamp proof is included. The OpenTimestamps, Bitcoin and RFC 3161 sidecar providers are simulation stubs; they return unsuccessful/unverified results and cannot establish external assurance.

## Run the evidence assessment

Python 3.9+ is sufficient; the verifier and its regression suite use only the standard library. Run from the repository root:

```bash
python tools/verifier/vcp_verifier.py \
    evidence/01_trade_logs/vcp_tv_events.jsonl \
    -s evidence/04_anchor/security_object.json \
    -a evidence/04_anchor/anchor_reference.json
```

Expected exit code: **2**. This is an incomplete assurance assessment, not a successful Silver validation.

| Exit code | Meaning |
| --- | --- |
| 0 | Only available with `--integrity-only`: the selected internal checks passed. No conformance or certification conclusion. |
| 1 | Invalid evidence or input error, including a missing explicitly requested file, malformed JSON, a root/count mismatch or an anchor bound to a different root. |
| 2 | The selected internal checks passed, but Silver conformance is not established. |

An omitted security object means the Merkle root was **not checked**. An omitted anchor is **NOT_PROVIDED**. Unknown, claimed external, pending or purportedly confirmed anchor metadata is **UNVERIFIED**: the tool has no external-proof verification backend. A provider name, transaction ID, local root match or claimed confirmation count cannot produce Silver success.

## What is actually checked

1. **Event hashes:** Recompute SHA-256 over the PoC's selected fields and Python JSON serialization (`sort_keys=True`, compact separators, `ensure_ascii=True`). This is not a general RFC 8785 implementation.
2. **Sequence continuity:** Compare adjacent `merkle_index` values when present. This does not independently establish that all real-world events were captured.
3. **PrevHash:** Compare optional links with the previous event hash.
4. **Merkle root and event count:** Compare with the supplied security object. The PoC uses RFC 6962 domain-separation prefixes but duplicates odd nodes; this is not a full RFC 6962 tree algorithm/conformance check.
5. **Anchor binding/classification:** Compare the anchor's declared root with the computed collection root. `local` / `local_file` is **LOCAL_ONLY**, never external assurance.

## What is not verified

- Ed25519 signatures or signer identity. Signatures and a public key are included but not validated by this CLI.
- External timestamp proofs, chain inclusion, timestamp-authority trust or the Silver 24-hour cadence.
- Completeness against an independently authenticated source or protection against coordinated rewriting of all local evidence.
- Full VCP conformance, regulatory compliance or certification.

The `tier: "SILVER"` fields in source events are declared targets, not assessment results. They remain unchanged because they are covered by the existing hashes/signatures. A new anchor obtained today would not retroactively prove timely anchoring of the historical events.

## Date provenance

The sample events carry times from **2025-01-15 10:00 to 13:15 UTC**. The security object, public-key metadata and local anchor carry times from **2026-01-17 13:00:44.412519 to 13:00:44.413196 UTC**. These are different kinds of self-reported timestamps, not a verified external chronology.

The previous `evidence_index.json` pack `created_at` was `2025-01-17T00:00:00Z`, preceding the included artifact metadata. No evidence establishes the exact original pack assembly time. It is now `null` (unknown), with the old value, observed date ranges, correction time and reason retained in `metadata_correction`. The initial-release changelog uses the repository import commit date, **2026-01-17**, explicitly labeled as such. Original event logs, signatures, roots, security object, public-key metadata and local anchor bytes are preserved.

## Regression and tamper tests

```bash
python -m unittest discover -s tools/verifier -p 'test_*.py' -v
python evidence/03_tamper_detection/tamper_detection_test.py
```

The regression suite covers local/missing/unsupported anchors, spoofed provider confirmation metadata, wrong roots and counts, malformed or missing files, corrupted event lines, altered events, simulated-provider behavior, metadata provenance and exact regeneration of the saved report.

## Work required before a future Silver claim

Provide a real external proof bound to the exact event collection root, implement provider-specific cryptographic proof verification and trustworthy time/chain validation, and demonstrate the applicable anchoring interval. Verify signatures and all remaining normative requirements separately. External anchoring alone is not a complete conformance assessment or certification.
